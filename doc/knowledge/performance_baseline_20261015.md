# 当前版本进程内性能基线（2026-10-15）

## 环境与可复现范围

- 代码：HEAD `0d25066` 加本轮日志分类、共享读取契约及上一轮限流/Panic 日志的未提交工作树。
  并非 `0d25066` 原始提交的测试结果；验收时请保留实际工作树 diff。
- 实际运行：`go1.27.2 darwin/arm64`，CPU Apple M1 Pro，macOS `27.0.1`。
  go.mod 声明仍为 Go 1.24.0 / toolchain go1.24.10，不应混同实测工具链。
- `-cpu=4` 固定 GOMAXPROCS=4。物理核心数、内存及机器空闲负载本轮未确认
  （硬件 sysctl 读取受限）；未采样 CPU/RSS，不做资源饱和结论。
- 运行命令（根目录）：

```bash
GOCACHE=/tmp/gin-finapi-gocache go test ./tests/bench -run '^$' -bench BenchmarkAPI -benchtime=5000x -count=3 -cpu=4
```

每场 5,000 次，预热 100 次；一个合成 Key/产品/32 字节 phone，6 个结果变量。
真实 SetupRoute（Recovery/CORS/Logger/限流）、JSON 参数/签名校验、授权、Handler、SID、
配置 Reader/LRU、映射与异步文件日志；Redis/Mongo 替换为无延时内存源/查询函数。
缓存默认容量 1000/10000/1000，回源并发 4，单次读取超时 1s，无定时刷新；
限流次数设置为整型最大值/1min，不测限流拒绝。文件队列 10,000 条，字节预算 64 MiB。

耗时包含每次 httptest 请求构造、处理及响应解析；QPS 用请求批次墙钟时间计算，不含预热、
排序和结束后排空文件日志时间。平均延迟为各请求耗时平均值，并发下不是 1/QPS。
百分位用排序后 nearest-rank。文件写入仅到 OS 缓冲，不代表 fsync；测试退出核对全部日志行数。

## 结论与后续

本数据只建立可复跑的当前代码 CPU/内存处理路径参考，不承诺上述吞吐，也不代表端到端接口延迟。
并发 32 的尾延迟存在明显波动，本轮没有足够采样/剖析证明根因，不据此调整锁、池或日志架构。
未执行优化前后对比；这是后续可比实验的起点，不声称已经获得性能提升。

真实 Redis/Mongo、真实数据量与索引、gzip 数据体积、Redis 日志写入/重试/丢弃、网络与 TLS、
混合失败请求、冷缓存和持续压力下资源曲线：均待在明确授权的隔离环境建立基线。
生产 SLO 和验收阈值待确认。下次比较必须保持相同工具链、硬件、并发、数据与日志参数，
建议增加足够长的持续测试、CPU/堆/锁剖析；不将旧 ab 数值当作当前版本回归门槛。
