**测试时间**: 2025-11-15

**测试环境**: macOS 15.3.2, Go 1.23.3

## 📋 测试概述

本次压测旨在评估 Airis 系统的性能表现，识别系统瓶颈，为生产环境部署提供参考数据。

### 测试接口
1. **Health 接口** (`GET /health`) - 轻量级健康检查接口
2. **Loan 接口**（历史压测为 `POST /loan`；当前接口为 `POST /api`）- 包含 MongoDB 查询、Gzip 解压等操作；历史结果不代表当前契约的性能。

## 📊 性能瓶颈分析

### 1. 并发连接数限制 ⚠️

**现象**: 并发超过 150 时出现连接重置  
**原因**: 
- 系统 TCP 连接数限制（macOS 默认限制较低）
- Go HTTP Server 的默认配置限制

**建议**:
```go
// 在 main.go 中增加服务器配置
srv := &http.Server{
    Addr:           ":8082",
    MaxHeaderBytes: 1 << 20,
    ReadTimeout:    10 * time.Second,
    WriteTimeout:   10 * time.Second,
    IdleTimeout:    120 * time.Second,
}
```

### 2. 长尾延迟问题 ⚠️

**现象**: 在 100 并发 5000 请求场景下，98% 以上请求延迟显著增加（200-400ms）  
**可能原因**:
- GC (垃圾回收) 暂停
- 并发竞争导致的锁等待
- MongoDB 连接池资源竞争

**建议**:
- 调整 GOGC 参数优化 GC 频率
- 检查代码中的锁使用情况
- 监控 MongoDB 连接池使用率

### 3. MongoDB 连接池配置

**当前配置**:
- 最大连接池: 100
- 最小连接池: 10

**分析**: 连接池配置合理，足以支撑当前并发量

### 4. 中间件性能影响

**已启用中间件**:
- Recovery (异常恢复)
- CORS (跨域处理)
- Logger (请求日志)
- RateLimit (限流: 100,000 req/s)

**影响**: 中间件对性能影响较小，日志中间件可能在高并发下产生 I/O 瓶颈

## 💡 性能优化建议

### 短期优化（1-2 天）

1. **调整系统连接数限制**
   ```bash
   # macOS 调整最大文件描述符
   ulimit -n 65536
   ```

2. **优化 HTTP Server 配置**
   - 增加 ReadTimeout、WriteTimeout
   - 调整 MaxHeaderBytes

3. **优化日志中间件**
   - 使用异步日志写入
   - 考虑采样日志（只记录部分请求）

### 中期优化（1 周）

1. **引入连接池监控**
   - 监控 MongoDB 连接池使用情况
   - 实时追踪慢查询

2. **优化 Gzip 解压性能**
   - 考虑使用 sync.Pool 复用解压缓冲区
   - 评估是否需要 Gzip 压缩（权衡存储与性能）

3. **添加性能监控**
   - 集成 Prometheus + Grafana
   - 监控 CPU、内存、响应时间

### 长期优化（1 个月）

1. **水平扩展方案**
   - 部署多实例 + 负载均衡
   - 实现服务高可用

2. **缓存优化**
   - 引入 Redis 缓存热点数据
   - 减少 MongoDB 查询压力

3. **数据库优化**
   - MongoDB 索引优化
   - 考虑读写分离

## 🏆 结论

### 系统优势
✅ **低延迟**: P50 响应时间 6-13ms，性能优异  
✅ **高稳定性**: 在推荐并发数下，失败率为 0%  
✅ **良好的并发处理**: 支持 100-120 并发，QPS 可达 7,000-16,000  

### 主要瓶颈
⚠️ **并发连接数限制**: 超过 150 并发会出现连接重置  
⚠️ **长尾延迟**: 高并发下存在 P98-P99 延迟尖刺  

### 生产环境建议
- **推荐部署规格**: 4 核 8GB 内存
- **推荐并发上限**: 100 并发/实例
- **推荐 QPS 上限**: 6,000 req/s/实例
- **建议实例数**: 根据业务流量，建议至少 2 个实例保证高可用
