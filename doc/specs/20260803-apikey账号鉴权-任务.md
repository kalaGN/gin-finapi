# API Key 账号鉴权：任务

> 状态：草案；依赖 [`20260803-apikey账号鉴权-设计.md`](20260803-apikey账号鉴权-设计.md)
> 完成评审后实施。本文不扩展账号过期、IP 白名单或并发限制。

## 目标与实施边界

将 `/loan` 的现有“`apikey` 仅校验非空 + 全局 secret 验签”替换为：

1. 从内存 -> Redis -> MySQL 按顺序查找账号，未命中、过期或依赖失败时读下一层。
2. 三层都不能返回 60 秒内的新鲜记录时，调用运营中心完整批量账号接口。
3. 只允许 `status == 1` 的账号使用其独立明文 secret 验签。
4. 未知/禁用账号和签名错误返回 HTTP `200`；鉴权系统故障返回 HTTP `503`。
5. 不改变 `/loan` 请求字段、签名拼接格式、Mongo 数据格式和成功响应。

实施期间不运行 `cmd/init_mongo.go`、`cmd/init_mongo.sh` 或其等价数据重建操作。

## 依赖顺序

```text
生产契约/配置门禁
  -> 账号模型与结果语义
      -> 运营中心客户端 -> 独立 Mock 服务
      -> MySQL / Redis / 内存单层存储
          -> 分层查询与批量回源
              -> 签名与日志安全改造
                  -> /loan 鉴权接入
                      -> 启动/关闭接线 -> 集成与发布验证
```

## 风险与阻塞项

| 风险/阻塞 | 影响 | 缓解或门禁 |
| --- | --- | --- |
| 真实运营中心不是完整快照 | 不能安全判定 Key 不存在 | 先更新设计为分页/增量契约，不复用当前负缓存语义 |
| 全量快照过大 | 内存、带宽和延迟不可控 | 上线前确认上限并强制 Body 限制，超限 fail closed |
| MySQL 驱动未确认 | 无法完成持久层和启动接线 | 任务 5、12 前完成审核，不自行选版本上线 |
| 明文 secret 持久化 | 数据库/备份读权可伪造签名 | 加密传输、静态/备份加密、最小权限、访问审计和保留周期必须先评审 |
| 旧日志记录完整 Body | API Key、签名和手机号泄露 | 任务 10 是上线前强制门禁 |
| 分层错误被误当未命中 | 误拒绝、缓存污染或绕过鉴权 | 使用显式结果类型，每层覆盖故障测试 |
| 切换后仍回退全局 secret | 未知账号可绕过账号鉴权 | 主链路移除全局 secret 依赖并增加安全回归测试 |

## 回滚边界

- 代码回滚会恢复“API Key 仅校验非空 + 全局 secret”的安全降级行为，必须明确授权，不作为默认故障降级。
- `accounts` 表和 Redis 鉴权 Key 在回滚时保留；Redis Key 按 TTL 自然过期，不执行破坏性删除。
- DDL 是新增表，首期不提供自动 drop 脚本；如需删表必须单独评审数据保留和备份。
