# nonce 纳入签名：设计

创建日期：2026-10-12。依据用户确认的 CryptoJS MD5 拼接规则实施。

## 范围与现状

现有 LoanAuth 仅签 apikey、pcode、phone、timestamp，Request 没有 nonce。
本次增加 JSON nonce，沿用现有请求样例的字符串形态，必填且非空；不截断或去除前导零。
不引入防重放存储、依赖、接口版本或缓存重构，不移动鉴权文件。

## 签名契约

```text
apikey=<原值>&nonce=<原值>&pcode=<十进制整数>&phone=<原值>&timestamp=<十进制毫秒整数>&key=<凭据secret>
```

参数按 key 排序，按用户要求直接拼接，不进行 URL 编码或 JSON 序列化，再计算大写 MD5。
phone 在截断/转换前签名。保留服务端接受小写合法签名的现有兼容行为。
只读取 JSON Body；URL Query 和 Header 不替代这些字段。
nonce 缺失/空串：400/1001、nonce is required；null/非字符串：400/1000、nonce must be a string。
参数场景文案放 pkg/rescode。签名不匹配维持 400/2002，其他已有错误码不变。

## 兼容、安全与发布

客户端必须同步增加 nonce 并重新计算签名，不提供旧四字段签名回退。
纳入签名只能防止 nonce 被修改；没有服务端去重，同一请求仍可能在时间窗口内重放。
沿用 Body 64 KiB 上限，不额外发明 nonce 长度或字符规则。
回滚须协调客户端签名规则；不执行部署、初始化、提交或推送。

## 实施与验收

1. 新增失败测试，覆盖缺失、空串、类型错误、篡改、旧签名、前导零和小写签名兼容。
2. Request 与 LoanAuth 增加 nonce，复用现有排序和 MD5 工具。
3. 同步 HTTP 测试 Fixture、Postman/Apifox 前置脚本、README、Rules 和 Knowledge。
4. 以独立固定签名向量验证拼接规则，而非只用同一工具生成和验证。
5. 运行 go test -race ./...、独立 Redis CLI 测试、go vet、go build、go mod verify、git diff --check。

## 验证结果

- 新增测试先复现旧实现接受四字段签名、拒绝五字段签名，再修复并通过。
- 全量 go test -race ./...、独立 Redis CLI 测试、go vet ./...、go build ./...、go mod verify 通过。
- 固定向量使用合成参数：独立 Node MD5 与 Go 工具结果一致，前导零变化会导致签名失效。
- 20 个 Postman 前置脚本在离线模拟环境执行，18 个正常签名逐条符合用户明确的五字段原文；另外两项为故意错误/缺失签名用例。
- 相对链接、格式和 git diff --check 已检查；真实 Apifox 导入执行与线上请求未验证。
