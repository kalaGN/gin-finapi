## 范围与现状

现有 LoanAuth 仅签 apikey、pcode、phone、timestamp，Request 没有 nonce。
本次增加 JSON nonce，沿用现有请求样例的字符串形态，必填且非空；不截断或去除前导零。
不引入防重放存储、依赖、接口版本或缓存重构，不移动鉴权文件。

## 签名契约

```text
apikey=<原值>&nonce=<原值>&pcode=<十进制整数>&phone=<原值>&timestamp=<十进制毫秒整数>&key=<凭据secret>
```

参数按 key 排序，按用户要求直接拼接，不进行 URL 编码或 JSON 序列化，再计算大写 MD5。
phone 在截断/转换前签名。保留服务端接受小写合法签名的现有兼容行为。
只读取 JSON Body；URL Query 和 Header 不替代这些字段。
nonce 缺失/空串：400/1001、nonce is required；null/非字符串：400/1000、nonce must be a string。
参数场景文案放 pkg/rescode。签名不匹配维持 400/2002，其他已有错误码不变。

## 兼容、安全与发布

客户端必须同步增加 nonce 并重新计算签名，不提供旧四字段签名回退。
纳入签名只能防止 nonce 被修改；没有服务端去重，同一请求仍可能在时间窗口内重放。
沿用 Body 64 KiB 上限，不额外发明 nonce 长度或字符规则。
回滚须协调客户端签名规则；不执行部署、初始化、提交或推送。
