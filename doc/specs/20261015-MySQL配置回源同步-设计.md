# MySQL 配置回源与 Redis 同步：设计

## 已确认需求与现状

用户要求在本机既有 `fin_api` 创建客户、API Key、产品及 Key 产品授权四表，参考 init 写样例；
实现 Redis 读取失败后读取 MySQL，以及 MySQL → Redis 同步。用户确认一个客户多个 Key，
定时同步默认开启，默认周期 5 分钟，并保留手动命令与关闭开关。

本机只读确认 MySQL 9.6.0，fin_api 无既有表。应用此前只有 Redis 读取器与内存缓存，
无 MySQL 驱动；JSON 凭据/授权的 version=1，status=0/1，expires_at 为 Unix 秒、0 永久。
产品映射 JSON 六变量下标源自 cmd/init_redis.go；Mongo 数据格式及查询流程不变。
旧 Rules 的“Redis 错误不回源”和“禁止自动写映射”被本次明确需求覆盖，仅限启用 MySQL 时。

## 边界与数据

- 仅操作明确授权的本地 fin_api；优先 laya_app，root 仅作建表权限不足的备用，不扩大操作到其他库。
- 不重建库/表、不 DROP/TRUNCATE，不运行 Mongo init，不清空 Redis，不提交真实凭据或 .env。
- api_customers：id、name、status、remark、created_at、updated_at。
- api_keys：id、customer_id、name、唯一 api_key_digest、secret_ciphertext、secret_key_id、
  status、expires_at、remark、时间字段。Key 摘要与 services.Digest 一致，不存原 Key。
- api_products：pcode 主键、name、variable_map JSON、remark、时间字段。不增加全局产品开关。
- api_key_products：联合主键(api_key_id,pcode)、status、expires_at、remark、时间字段。
  外键 RESTRICT；默认禁用，样例显式启用。不引入余额、套餐或计费字段。
- 客户禁用会折算到每个 Key 的有效状态，授权仍独立绑定 Key；到期语义不变。
- secret 使用独立本地环境密钥 AES-256-GCM 加密，密文包含 nonce/tag，AAD 绑定摘要及密钥 ID；
  不与 phone 处理相关。单密钥 ID，轮换须先迁移密文；不把密钥写入库或源码。
- SQL 是可审查迁移，初始化工具显式执行，仅创建缺失表；样例事务写入、不覆盖已存在记录，
  发现固定样例 ID/摘要与其他数据冲突即回滚。DDL 不具备跨语句事务，失败报告已创建部分可重试。

## 读取链与错误语义

内存 → Redis → MySQL（MYSQL_ENABLED=false 时维持原 Redis-only）。
使用现有 app/configdata 目录中的显式回源适配器，不改变通用 Source 的默认错误停止语义。
Redis 明确命中（含禁用/到期）直接返回；缺失、连接错误、超时或损坏记录可读取权威 MySQL。
调用方取消或整个读取预算耗尽不再启动下层读取；各源有独立超时，总预算覆盖 Redis+MySQL。
MySQL 明确缺失为认证/授权拒绝或产品异常，MySQL 故障为服务异常，损坏 MySQL 记录失败关闭。
不缓存失败；回源成功可以写内存，不在请求路径写 Redis，关闭内存时也保留 MySQL 回源。
内存仍不检查年龄，状态/到期逐请求检查；同步传播不是立即撤权保证。

## MySQL → Redis

MYSQL_SYNC_ENABLED 默认 true（仅 MYSQL_ENABLED=true 时启用），5m 周期，启动后异步执行一次；
另提供手动 dry-run/apply 命令。只读取 MySQL，不从日志 Redis 读取或写 request_log。
先获得 Redis 有界租约锁，再在 MySQL 一致性只读事务中读取三类完整快照，完整校验/解密后发布。
发布用 Lua 检查锁令牌并隔离更新现有三种 String Key，不改变 JSON 字段、Key 或到期语义。
清单只记录本工具已发布的精确 Key；仅清理由清单管理且从 MySQL 删除的键，不 SCAN/FLUSHDB。
禁用/到期状态同步保留，用于拒绝；不把坏数据、部分读取或数据库故障当作空快照发布。
SQL 读取、解密、校验或锁检查失败不写新快照；Redis 故障时 MySQL 回源仍可服务。
Lua 提供执行隔离而非事务回滚：Redis OOM/运行时故障可能部分写入，连接断开时结果可能未知；
下一轮完整同步可幂等修复，不能宣称任意失败都保留完整旧快照。运维须监测内存、错误和同步结果。
单 Redis 实例，当前不承诺 Redis Cluster。同步成功后刷新本进程已缓存项；其他实例依原周期刷新。
本功能的发布操作会覆盖 MySQL 中同名实体对应的 Redis 配置，其他未托管配置不清理。

## 架构、配置与生命周期

新增 pkg/mysql（database/sql + 锁定的官方兼容驱动），复用 app/configdata 与 app/services，
不新增 app 子目录。共享产品映射校验归 services，避免 MySQL 反向依赖 Redis 解析器。
pkg/redis 实现发布与租约，app/configdata 编排同步与关闭；bootstrap 显式装配，main 不增加逻辑。
MYSQL_ENABLED 默认 false，保留原应用兼容；本机 .env 显式开启 MySQL 和默认定时同步。
连接/查询/写入/同步预算、池参数、TLS 和加密密钥独立配置，严格校验，不输出 DSN 或驱动原始错误。
关闭先停止同步 worker，再关闭 Reader/MySQL/Mongo/Redis/日志，沿用现有停机预算。

## 待确认及风险

本地 Redis 配置为 localhost:6379 DB0；实际同步前检查目标与现有同名键，验证优先使用隔离实例。
不承诺跨 MySQL/Redis/多进程内存原子一致性；正常同步+缓存传播有延迟。
MySQL 加密不代表 Redis/内存没有明文 secret，仍须限制 Redis、日志及环境配置访问。
回滚关闭 MYSQL_ENABLED 即恢复 Redis-only；保留新增表，不自动删除数据。已发布 Redis 需按授权恢复。
