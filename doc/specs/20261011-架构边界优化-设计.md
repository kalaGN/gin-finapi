# 架构边界优化：设计

状态：2026-10-11 用户要求按前一轮审计顺序修复 P1、P2，授权实施。

## 目标与事实来源

基于 main.go、bootstrap/route.go、pkg/mongo/client.go、mongo.go、Redis 两个读取器、
LoanAuth、LoanHandler、cmd/init_redis.go 与 .github/workflows/ci.yml。
单 Go module、小型查询服务；不引入完整 Repository 分层、容器或新依赖。
保持 HTTP、认证、phone、业务码、t/v、gzip/CSV、产品配置的行为契约。

## 顺序、职责与验收

1. P1 生命周期：实施既有启动关闭 Spec，main 只负责信号、Run、脱敏报告与退出码。
   先补服务错误/取消/独立关闭 Context/强制 Close/错误合并测试，迁移已有关闭断言。
2. P1 Mongo：同包新增 Store，实例保存配置并拥有懒连接管理器；主链路不依赖全局配置或客户端。
   查询参数仅携带查询值与字段映射，连接、数据库、集合和超时来自实例。
   用户后续确认不保留全局兼容入口：删除 GetMongo、GetClient、包级 Close 与其配置 DTO，
   同时删除无调用的旧连接函数；Store 是唯一查询/关闭入口，其余 P3 遗留模块不清理。
   补实例隔离、注入配置和无初始化关闭测试，保留初始化重试、并发与 BSON 特征测试。
3. P2 CLI：保持现有单文件命令，CI 显式 vet、race test、编译 Redis CLI；不运行初始化程序。
4. P2 查询编排：在 app/loan 添加轻量查询用例，通过函数依赖加载映射和查询数据，
   bootstrap 仅装配。错误转换到业务语义，Handler 不再导入 Redis/Mongo。
5. P2 认证边界：app/auth 定义凭据快照与错误；Redis 负责存储解析，中间件只依赖认证语义。
   旧 Redis 类型/错误可用别名兼容，保持记录 schema、禁用/到期与 HTTP 返回不变。
6. P2 Redis：保留两个客户端所有权，不擅自合池；集中重复客户端选项并测试，明确
   REDIS_POOL_SIZE 作用于每个池，不是全应用连接总上限；不新增缓存、重试或配置变量。

## 结构、风格与范围

新增 bootstrap/app.go、lifecycle.go 及测试；Mongo Store 在现有 pkg/mongo 同包；
app/loan、app/auth 是实际业务/认证边界，不增 CRUD 接口或通用框架。
文档沿用现有 doc 目录；中文注释、Go 1.24、gofmt。
例如 `Query(ctx, phone, pcode)` 只处理流程，数据访问由注入函数承担。
