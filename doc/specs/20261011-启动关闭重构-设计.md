事实来源：main.go、main_test.go、bootstrap/route.go、pkg/logger/logger.go、pkg/mongo/mongo.go。

## 范围与职责

- main.go：创建 SIGINT/SIGTERM 的 signal.NotifyContext，调用 bootstrap.Run；Run 返回后解除
  信号注册，最后统一记录无敏感信息的失败摘要并决定退出码。禁止 goroutine 或底层组件 Fatal。
- bootstrap/app.go：环境加载、logger/config 初始化及校验、Gin 模式、NewRouter 和 Server 装配。
- bootstrap/lifecycle.go：HTTP 运行、错误通道、停止条件及资源关闭顺序。
- bootstrap 中对应 testing 测试：注入服务生命周期函数测试各个分支，不引入新框架或依赖。
- 保留现有 NewRouter 和 Handler 的依赖注入，不新增容器、Repository 或无用途的管理层。

main 保持短入口；配置、服务和清理错误向上返回，例如 `return fmt.Errorf("启动 HTTP: %w", err)`。

## 启动和错误通道

1. 按现有顺序加载可选 .env、初始化日志、加载并校验配置、装配路由和 HTTP Server。
2. 明确 .env 不存在可忽略；存在但读取或解析失败应返回错误，不再吞掉该错误。
3. 不忽略有错误返回值的启动操作；可直接使用已校验的配置值，避免重复配置加载。
4. ListenAndServe 运行在单个 goroutine 中，通过容量为 1 的错误通道向主流程发送终止结果。
   仅发送一次，通道不用额外关闭；不会因主流程开始关闭而堵塞发送者。
5. 主流程 select 等待停止 Context 或服务退出；两条路径都进入统一清理。
6. http.ErrServerClosed 不作为服务错误；其他服务错误保留原因并合并清理错误。
7. 清理完成后等待服务 goroutine 结束，额外最多 5s 防止异常实现无限等待；使用可控函数和通道测试，不靠 sleep 猜时序。
8. 正常信号停止且清理成功返回 nil，退出码 0；启动、服务或关闭失败返回 error，退出码 1。

## 关闭策略（需确认的行为调整）

- 先停止 HTTP 接收并等待请求，再关闭 Mongo，避免正常关闭时数据库先断开。
- HTTP Shutdown 使用独立、未被停止信号取消的 Context，最多等待 5s。
- Shutdown 失败或超时则调用 HTTP Close，停止仍存活的连接；仍保留原关闭错误。
- Mongo Close 随后使用新的独立 Context，最多等待 5s，不继承 HTTP 已耗尽的时限。
- HTTP/依赖预算合计约 10s，另有服务退出等待 5s 保护；HTTP 强制 Close 和函数调度不作为严格硬时限保证。
- 任一阶段失败仍尝试后续关闭，用 errors.Join 保留服务、HTTP 和 Mongo 的错误链。
- 尚未初始化的 Mongo 客户端关闭保持安全；不为清理主动创建连接。

## 兼容、安全与非目标

- API、鉴权、phone、业务码、Mongo t/v、gzip/CSV、变量映射不变。
- 保留端口、Gin 模式、10s 读写超时、1MiB Header 限制及懒连接行为。
- 不修改配置文件、依赖、CI、部署，不新增健康检查或启动 Mongo Ping。
- 异常日志不得直接输出可能包含密码、DSN、请求值的底层错误；错误链留在内部用于分类和测试。
- 不运行数据初始化 CLI，不访问现有业务数据库，不重启现有服务，不提交或推送。
- 不新增监控平台、自动重试或熔断。真实生产终止宽限时间未知，10s 关闭预算是否匹配部署待确认。
