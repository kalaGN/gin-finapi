# 异步请求日志：设计

创建日期：2026-10-13。用户确认请求日志可选文件或独立 charge_redis；响应处理后异步写入，
Redis key 固定 request_log，首次失败后重试 2 次，仍失败丢弃；本轮不实现消费任务。

## 契约与方案

- REQUEST_LOG_OUTPUT=file|redis，标准环境加载默认 file；文件 REQUEST_LOG_FILE 默认 request.log。
- REQUEST_LOG_QUEUE_SIZE 默认 10000，正整数。有界队列满时丢弃并由后台记录错误，不阻塞响应。
- 独立 ChargeRedis 使用 CHARGE_REDIS_ADDR/PASSWORD/DB/POOL_SIZE/TIMEOUT，不回退认证 Redis。
  redis 模式地址必填，其余默认空密码、DB 0、池 10、超时 1s；file 模式不校验闲置 Redis 配置。
- 只有请求完成日志切换后端；内部错误、启动和缓存日志仍使用原应用 Logger。
- 每条 JSON 保留 method、path、http_status、duration_ms、success、charge，并带日志时间与固定消息。
  不读取或缓存 Body，不记录认证凭据、手机标识、响应业务数据或原始驱动错误。
- pkg/logger 现有包内增加后台 writer，使用标准 io.Writer 和函数注入；不在 app 下增加目录或新依赖。
  Logger 在 c.Next 后只格式化、复制日志并非阻塞入队；单 worker 写入文件或 RPUSH request_log。
- 每次 Redis 写入独立超时，不使用已结束的请求 Context；驱动关闭自动重试，worker 控制最多 3 次尝试。
  重试间隔建议 100ms、200ms，可被关闭 Context 中断；文件失败不重试，记录安全错误后处理下一条。
- 请求线程不做日志后端 I/O，也不为每请求启动 goroutine。入队完成不等于客户端已收到响应。
- 进程关闭先排空 HTTP，再在既有依赖关闭预算内排空日志；预算耗尽取消发送，丢弃余项，关闭后端。
  并发写入/关闭必须安全，构造失败与中途装配失败也须清理资源。main 保持不变。
- 对直接构造 AppConfig 的调用方，空 RequestLog.Output 保留注入 Logger 的行为；标准 Load 始终解析为 file/redis。

## 风险与非目标

重试可能在服务端已成功、客户端超时的场景产生重复记录，消费任务必须考虑幂等。
内存队列、有限重试和退出预算都允许丢失，charge 是标记，不能当作可靠的唯一计费账本。
不执行 LTRIM、EXPIRE、清库或消费；Redis List 可持续增长，须由后续消费者和运维管理容量。
文件采用追加写，不自动轮转；需要另行配置轮转/保留策略，不在本轮增加部署设施。
现有 Gin Recovery 和日志出口保持，Panic 日志不声称已统一进入此请求完成队列。

go test -race cmd/init_redis.go cmd/init_redis_test.go、git diff --check；仅 gofmt 修改的 Go 文件。
