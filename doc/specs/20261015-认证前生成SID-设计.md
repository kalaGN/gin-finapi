# 认证前生成 SID：设计

## 目标与当前事实

用户要求将 SID 放到认证前生成。当前 Handler 在认证和 phone 转换后调用
`utils.GenerateSID("100", 29)`，失败请求无可复用的业务 SID。
本次以明确要求覆盖历史 Spec 中“先转换后 SID”的处理顺序，不更改签名或查询格式。

## 方案与边界

- 在已有 app/middleware 新增 RequestSID，绑定在 POST /api 的 LoanAuth 前；
  不改变全局 Recovery/CORS/Logger/限流顺序，不给 health、404、预检及限流拒绝生成 SID。
- bootstrap 注入既有 crypto/rand SID 生成器；保持前缀 100、随机部分 29 字符。
- 通过 pkg/request Context 保存 SID。Handler 只依赖查询与日志，不再生成 SID。
  认证成功但缺少 SID 属于装配错误，返回既有 500/9001，禁止临时补生成掩盖问题。
- SID 生成失败（包括空结果）先返回 500/9001，不读取认证源、不查询；
  这是前移后有意改变的错误优先级，不泄漏随机源原始错误，不使用可预测 SID 降级。
- 成功响应仍返回该 SID；错误响应仍保留既有空 sid，不自动给所有错误响应填 SID。
- 完成日志与 Handler 诊断日志增加 sid；认证/参数错误能在完成日志中查到该 SID。
  用户后续明确要求删除 request_id，统一以 SID 关联，不新增响应 Header。
- 移除 request_id 生成器、Context 键、日志字段及专用测试；保留 SID 关联回归，
  增加断言确保完成/诊断日志不再输出 request_id。health、404、预检、限流拒绝、SID 生成失败
  的日志 sid 为空，没有逐请求关联标识；保留状态、分类和时间等字段，不制造备用标识。

## 实施顺序与验收

1. 添加认证前 SID 可见、单次生成、认证失败阻断、SID 失败阻断及健康检查不受影响的用例。
2. 添加中间件/Context，移除 Handler SID 生成依赖，更新装配和相关测试。
3. 校验成功响应 SID 等于日志 SID，错误响应仍空；未知字段、签名与原错误码回归不变。
4. 更新索引/Rules/Knowledge；gofmt、go test -race ./...、go vet ./...、go build ./...、
   go mod verify、独立 Redis CLI 竞态测试、git diff --check 和 Markdown 链接检查。

## 风险、性能与回滚

无数据迁移、依赖升级、新目录或外部操作；仅改本地代码和测试，不自动提交/部署。
无效 API 请求现在也消耗 SID 随机生成成本，但仍在全局限流之后，保持限流保护。
既有进程内性能报告为历史工作树结果，本次需复跑同参数基准；不外推生产容量。
回滚本轮源码可恢复旧生成位置；不改日志消费者既有字段，新增 sid 要求容忍额外字段。
删除 request_id 属于用户确认的日志字段变更，外部消费者如依赖旧字段需改为读取 sid；
仓库内消费者已检索，未发现业务使用，外部消费方状态待确认。旧实现可从 Git 恢复。

## 实施与验证

- RequestSID → LoanAuth → LoanHandler 已接通；Handler 构造函数不再接受 SID 生成器。
- 回归覆盖认证前可见、仅生成一次、失败阻断、空结果/缺失生成器、客户端 Header 不可信、
  Handler 缺少 SID 的装配错误、响应/日志 SID 一致及 health 无 SID 链路。
- 全量 `go test -race ./...`、`go vet ./...`、`go build ./...`、`go mod verify` 已通过。
- 同参数合成基准四场景各三轮通过，结果追加至 [基线报告](../knowledge/performance_baseline_20261015.md)。
- 未执行真实存储集成、初始化或部署；未自动提交。
- 后续删除 request_id：相关调用和两个专用文件已移除，可从 Git 恢复；
  成功/失败路径均增加“顶层日志无 request_id”断言，SID 关联测试保留。
  全量竞态、静态检查、构建及同参数合成基准再次通过。
