- 合法 JSON 请求/响应作为 JSON 值嵌入，非法 JSON 或文本作为字符串保留；不删除或脱敏请求体字段。
- 完整请求体可能含 API Key、sign、phone 和其他客户数据；这是用户新要求对旧脱敏规则的例外。

  success/charge 仍按业务码 0/3001 计算；http_status 单独保留。
- time 是日志生成时的 Unix 毫秒整数，不是后台 Redis 写入时间；异步写入、两次重试和丢弃策略不变。

## 实施与资源边界

Logger 在处理前最多读取既有 64 KiB 限制加一字节并恢复 Body，保留底层读取错误与 Close，
不绕过 LoanAuth 的 MaxBytesReader；正常合法请求完整记录，超限请求只保存前 64 KiB 并标记 input_truncated。
响应 writer 只旁路复制实际写入的响应，不替换返回内容。保留现有 Recovery/日志顺序，不宣称已统一 Panic 日志。
专用请求 JSON Formatter 移除顶层 msg，采用 UnixMilli；内部 Logger 不修改。
完整内容增大队列体积，补充 REQUEST_LOG_MAX_BYTES，默认 64 MiB；包含排队和正在写的字节，
与原条数限制同时生效。达到任一上限丢弃，不阻塞；预算仅限制队列载荷，不是进程总内存上限或性能基线。
不新增 app 目录、依赖、消费者、报警、部署或自动提交。

## 安全、容量与验收

运维须限制日志文件读取权限、charge Redis 访问和网络范围，并安排清理/保留策略；不能无限积压敏感日志。
本轮不自动删除 List 或日志，也不自动开启 TLS/修改部署；这些设置与保留周期尚待环境确认。
验证完整请求体（含未知 JSON 字段）、响应一致性、0/3001/异常业务码、非 JSON/空体/超限、
读取错误不被吞掉、无 Header/Query、毫秒整数、删除顶层 msg、字节预算与释放、异步并发/关闭回归。
使用合成凭据，运行全量竞态测试、vet、build、依赖校验、独立 Redis CLI 测试、格式和链接检查。
不执行真实客户请求、Redis/Mongo 写入或生产配置更改。
