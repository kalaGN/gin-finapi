# 限流生命周期与查询职责：设计

创建日期：2026-10-14。用户明确要求实施架构审查中的第 1、2 项，其余建议不在本轮范围。

## 当前实现与目标

- app/middleware/ratelimit.go 构造时启动清理 goroutine，无停止入口；bootstrap/route.go 未管理其关闭。
- app/Http/controllers/loan/index.go 内部 phoneLookupKey 承担业务标识转换。
- 目标：限流后台任务可启动、可等待关闭；转换规则归现有 app/services/，保持 HTTP 和数据契约。

## 方案、顺序与兼容边界

1. 先新增限流器构造、Start/Close、并发与清理测试，验证缺失的生命周期入口。
2. NewRateLimiter 只初始化；Start 幂等启动清理 worker；Close(ctx) 幂等发停止信号并按调用方预算等待退出。
   未启动时可关闭，关闭后不得重新启动；不改 IP 计数、窗口、429 JSON 或中间件顺序。
3. SetupRoute 显式启动 worker 并返回关闭函数；NewRouter 将其纳入依赖关闭，直接调用 SetupRoute 的测试也负责关闭。
   HTTP 先排空，再关闭限流 worker、缓存、Mongo、Redis 和请求日志；不改变原 5s 依赖关闭预算。
4. 在 app/services/ 新增 phone_lookup.go 纯函数 PhoneLookupKey，Handler 只调用其结果。
   所有 32 字节字符串截前 20 字节；64 字节十六进制返回转换不可用，64 字节非十六进制保持原值。
   其他值保留原函数行为；公开长度校验仍由现有中间件负责，不新增转换服务或重新哈希。
5. 保留转换→SID→映射/查询顺序；转换失败仍为 503/9002，且不生成 SID、不访问数据源。

## 测试、文件和风格

使用现有 Go testing、httptest 和竞态检查；测试放对应包。注释中文，修改文件 gofmt。
主要文件：app/middleware/ratelimit.go 及测试、bootstrap/route.go 及测试、
app/services/phone_lookup.go 及测试、app/Http/controllers/loan/index.go。
复用 Start/Close 显式生命周期，不引入通用管理器、接口层或新 app 子目录。
保持现有 Handler 回归断言，新增 Service 表驱动测试覆盖大小写、长度、非十六进制和错误分类。

## 风险、回滚与非目标

关闭与启动必须在同一锁下同步，防止重复启动、重复关闭通道或等待不存在的 worker。
SetupRoute 的返回值用于资源所有权，仓库全部调用方同步检查；没有外部 Go 调用方的已确认资料。
不修改签名、认证、phone 长度校验、API 路径、数据结构、依赖、配置或部署；不增加报警或日志重构。
数据迁移不适用；回滚仅撤回本次代码与文档。不自动提交、推送、重启或运行数据初始化。
