# 请求结果日志：设计

创建日期：2026-10-13。用户已确认日志增加整数 success、charge。

## 规则与范围

| 响应业务 status | success | charge |
| --- | --- | --- |
| 0 | 1 | 1 |
| 3001（未查得） | 1 | 0 |
| 其他或没有业务状态 | 0 | 0 |

这里指 JSON 的业务 status，不是 HTTP 状态码；charge 仅表示日志字段，不执行扣费。
响应内容、状态码、认证、查询及数据格式保持不变。不增加 app 目录、依赖、报警或部署。

## 实施方案

当前 app/middleware/logger.go 在 c.Next 后记录安全请求元信息，没有业务结果。
pkg/request 提供 typed JSON/AbortWithStatusJSON 响应出口，将 Response.Status 同时保存在
Gin Context；Handler 与认证中间件使用该出口，Logger 从元信息读取业务码并计算两个标记。
不复制、缓存或反序列化响应体，不记录敏感数据，不以 HTTP 200 推断业务成功。
限流 429、无匹配路由、health 无业务状态时取 0/0；不改写现有 Gin Recovery 和日志链路。
未来新增业务响应必须使用该出口，否则按无状态处理，不自动推断收费。
