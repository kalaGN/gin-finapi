# 业务场景回归补充：设计

## 需求、事实与边界

用户要求补充用例覆盖业务场景。当前跨包语句覆盖率80.7%，但不等于场景或分支覆盖率。
范围是已确认的/API认证授权查询、三类配置读链、同步、缓存管理、日志、初始化安全与生命周期。
依据AGENTS、Rules、现有Spec及当前源码/测试；未确认需求不编造为验收标准。

只补测试/测试替身/文档，不改业务代码、依赖、数据合同、生产配置或CI。不新增app目录。
发现契约与代码不一致先报告，不以现状猜测新规则，不通过删除断言或吞错误使测试通过。
不读本地真实.env，不连接开发/生产数据库，不运行Mongo初始化，不提交/推送。
测试使用标准testing、httptest和既有SQL/Redis替身，中文注释、表驱动、gofmt。

## 任务与验收

1. HTTP组合回归：补在bootstrap/config_cache_test.go；缓存开/关分别验证Redis缺失/损坏/故障
   回源、有效禁用/到期不绕过、MySQL缺失/故障、各级授权/映射错误、查询结果和phone分支。
   不只断言HTTP码，还断言业务码、SID、结果、是否触及后续查询。
2. 配置与存储边界：共享快照引用/状态/摘要校验、MySQL构造/TLS配置和安全错误、SQL授权坏数据，
   快照失败不发布部分结果、种子事务失败不提交；优先扩展既有测试文件。
3. 发布/CLI/启动装配：租约/释放/异常响应安全失败、dry-run失败不触碰Redis、默认同步开关及关闭。
   不为了覆盖main/log.Fatal而改生产代码或执行真实初始化。
4. 运行定向与全量race、跨包覆盖率、vet/build、独立CLI，记录场景矩阵和未验证项。

命令（仓库根目录）：

```bash
go test -race ./bootstrap ./pkg/mysql ./pkg/redis ./app/services
go vet ./...
go test -race ./...
go test ./... -coverpkg=./... -coverprofile=/tmp/gin-finapi-business-coverage.out
go tool cover -func=/tmp/gin-finapi-business-coverage.out
go test -race cmd/init_redis.go cmd/init_redis_test.go
go test -race cmd/init_mysql.go cmd/init_mysql_test.go
go test -race cmd/sync_mysql_redis.go cmd/sync_mysql_redis_test.go
go build ./...
go mod verify
git diff --check
```

## 场景覆盖管理

新增Knowledge矩阵记录每组已确认规则→实际测试函数→本轮验证结果。已有用例可复用，不复制填数。
语句覆盖率保持与之前相同的跨包口径，独立CLI单独统计，integration标签编译不能充当执行证据。
正常/拒绝/损坏/故障/取消/并发/隔离各有明确断言；并发等待用channel和有界超时。

## 不能由离线测试保证的范围

真实Redis Lua执行、MySQL约束和TLS握手、Mongo索引/故障恢复、多实例传播和生产容量，
只能由隔离集成或环境验证证明。沿用现有显式集成资产，未执行的场景标注未验证。
SHA-256转换和报警尚未实现，分别测试当前TODO响应/列为非目标，不能宣称已覆盖未来业务。
任何有限用例都不等于“所有可能输入、调度、故障均已穷尽”。验收以可审查矩阵为准。
