# 产品变量映射：设计

状态：2026-10-11 用户要求开发，方案已确认并实施，验证记录见末尾。

## 已确认需求与实施前事实

- 产品就是请求 pcode。
- Redis Hash 的 key 为 mongo_map，field 为 pcode 的十进制字符串，value 为 JSON 映射。
- 映射缺失或 JSON 无效返回产品异常；Redis 不可用返回服务异常。
- 当前映射硬编码于 pkg/mongo/codec.go；QueryFunc 仅传 phone，尚未传 pcode。
- pkg/redis 尚未进入主链路，已有 Get 吞掉错误且使用 Background，不能直接用于本需求。
- 依赖沿用 go.mod 的 go-redis v9.7.0，不新增生产依赖。

示例仅用于审查，不自动执行写入：

```text
HSET mongo_map 10001 '{"var100001":0,"var100002":1,"var100003":2,"var100004":3,"var100005":4,"var100006":5}'
```

## 接口与错误方案（已确认）

| 场景 | HTTP | status | msg |
| --- | --- | --- | --- |
| HGET 返回 redis.Nil，产品映射缺失 | 200 | 新增 6001 | 产品异常 |
| JSON 无效或映射定义不合法 | 200 | 新增 6001 | 产品异常 |
| Redis 连接、认证、读操作等失败 | 503 | 沿用 9002 | 服务暂时不可用 |

6001 由用户明确指定，本次新增 ErrProductException，归入产品错误分段；不改其他业务码。
HTTP 200 的产品异常沿用现有未查得业务异常的处理方式，不等同请求参数 pcode 格式错误。
Redis 读失败（包括该操作超时）统一为服务异常；不透传驱动错误，不误报产品缺失。
Mongo 未查得、超时、不可用或坏数据仍按原分类处理。

## 职责与数据边界

1. LoanAuth 继续按请求原值校验签名，pcode 校验范围不变。
2. LoanHandler 的注入查询函数传递请求 Context、phone 查询标识和 pcode。
3. bootstrap 装配编排：先 HGET mongo_map pcode，校验映射，再查询 Mongo 并按该映射解码。
4. 在现有 pkg/redis 内新增独立的产品映射读取能力，返回可分类错误；不复用吞错 Get，
   不改其他未启用的遗留 Redis 方法，不让 Mongo codec 直接访问 Redis。
5. Mongo 查询入口接收已校验映射，纯解码函数按传入 map 映射，删除生产路径中的硬编码默认值。
6. 每次请求读取 Redis，不先引入本地缓存、TTL、回写或自动重试策略。
7. 使用现有 REDIS_ADDR、REDIS_PASSWORD、REDIS_DB、REDIS_POOL_SIZE；新增 REDIS_TIMEOUT，
   默认 1s，正 duration，在配置加载时校验，作为单次 HGET 截止时间并继承请求取消。
8. Redis 客户端由启动装配初始化，避免每请求创建；补充资源关闭入口，仅接入 Redis 清理，
   不默许实施尚未确认的完整启动关闭重构。

映射值必须是非空 JSON 对象，字段名非空，值为非负整数；null、数组、字符串、负数、
小数、溢出索引和重复 JSON 字段拒绝为产品异常。不同字段允许引用相同索引，不自动补字段或改名称。
保留 ProcessUserData 的严格字段数量规则：CSV 长度必须等于最大映射索引加一。
因此某产品只映射部分列但没有覆盖最后一列时，不自动放宽长度校验；如需支持子集另行确认。
存储格式 t/v、BSON 二进制 v、gzip、CSV 整数文本不变；无 Mongo Schema 或数据迁移。

## 风险与发布回滚

- 新版本依赖 Redis 的可用性；部署前人工准备每个产品映射，缺少映射会返回产品异常。
- 映射更新会立即影响下一个请求的变量含义，修改前核对产品与 CSV 列序，并留存可回滚旧值。
- 不为上线自动执行 HSET；配置写入和部署另行明确授权。
- 回滚代码版本可恢复旧硬编码路径；Redis 映射保留，不自动删除，不涉及 Mongo 数据回滚。
- 现有 codec.go 中用户新增的 TODO 属于本需求标记，只在实际替换硬编码映射时处理。
- 不改依赖、部署、API 入参、签名或 Mongo 存储格式，不自动提交、推送或重启服务。
