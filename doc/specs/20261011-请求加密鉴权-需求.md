# Loan 请求契约与鉴权：需求

状态：已按用户最新澄清修正，实施完成。

## 背景与契约修正

此前将 phone 解释为 AES-256-GCM 密文，并强制解密，导致原有查询标识返回 400/1002。
2026-10-11 用户澄清 phone 为 MD5/SHA-256 等既有标识，授权恢复原值查询。
历史 HEAD 代码只要求 phone 是非空 JSON 字符串，直接用于 Mongo t 查询。
示例标识不是标准十六进制摘要；当前没有足够依据新增摘要长度、大小写或编码限制。
文档文件名保留以便追溯，原 AES 方案已撤销。

## 范围

- LoanAuth 单次解析 JSON，保持字段类型、pcode 范围、时间戳及签名校验。
- 使用 API_KEY 校验合法请求 apikey，以 SECRET_KEY 校验签名。
- LoanHandler 注入查询、SID 和 Logger；不直接读取配置。
- 签名使用原始完整 phone；32 位十六进制 MD5 查询前截取前 20 位，不改变大小写。
- 64 位十六进制 SHA-256 需后续服务映射为原手机号 MD5，再截前 20 位；目前仅 TODO，返回 503/9002，禁止本地重哈希或直接查询。
- 既有 20 位缩短标识及其他历史非空查询值保留原值兼容；不进行 AES 解密。
- 移除本轮 AES 工具、解密注入、PHONE_AES_KEY 必填配置和旧 AES 契约测试；
  用旧查询标识回归测试替代已撤销的加密约束测试。
- 保留安全元数据日志、64 KiB Body 限制、单 JSON 校验和限流配置。

## 非目标与兼容性

不实现多账号缓存/运营中心，不修改 Mongo 数据结构、签名算法或响应字段。
URL 中的认证字段及 nonce 与历史实现一致，不参与当前 JSON 签名。
API_KEY 仍必填，必须等于客户端 JSON apikey；该要求是用户已确认保留的认证改动。
旧 PHONE_AES_KEY 可留在本地 .env，但不再读取或必填；本轮不修改真实 .env。

## 验收

- 原有 20 位标识原样查询，32 位 MD5 按前 20 位查询；两者均以原完整请求字段签名。
- SHA-256 服务接入前返回 503/9002，不生成 SID、不查询 Mongo；转换服务契约另行确认。
- 请求格式/认证错误在查询前拒绝；无认证中间件的 Handler 拒绝访问。
- SID 失败、查询错误映射、请求取消和 /health 回归保持通过。
- phone、apikey、sign 不进入请求日志，无新增依赖或自动提交。
