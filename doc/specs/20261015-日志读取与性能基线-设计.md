# 日志读取与性能基线：设计

> 后续更新：SID 已按用户要求由 [认证前生成 SID](20261015-认证前生成SID-设计.md) 前移，
> 诊断/完成日志统一以 sid 关联，request_id 实现和字段随后按用户要求删除；
> 下文 request_id 方案仅为本轮最初实施的历史记录，不能作为当前规则。

## 范围与现状

对应用户确认修复的审计项 5、6、8。Handler 对未查得也输出 ERROR，诊断日志只有操作名；
Redis 适配器反向依赖 configdata 的键类型、摘要函数和损坏记录标记；缓存与直读重复判断
状态/到期。历史 ab 请求不符合当前认证契约，不能证明当前版本性能。

## 方案与兼容边界

- 内部 request_id 在日志边界创建，Handler 独立调用时按需创建。进程启动时间加原子序号，
  仅承诺单进程唯一，不信任客户端 Header，不新增响应 Header/字段，不代替业务 SID。
- 未查得不记异常日志；产品映射异常 WARN，其余查询异常 ERROR。固定 error_kind 区分
  unavailable、timeout、canceled、invalid_data、internal、sid_generation、phone_conversion。
  诊断日志只包含固定事件、操作、分类和 request_id，不包含原始驱动错误或请求数据。
- 完成日志仍保留已确认的完整 input/response_data 策略，并增加同一个 request_id。
- services 拥有 ProductKey、Digest、ErrInvalidRecord 和快照 Validate 策略。
  configdata 负责缓存、刷新、回源调度；Redis 负责键布局、读取、解析；不更改 JSON、
  Redis Key、HTTP、错误优先级、到期规则或缓存策略，不新增 app 目录和依赖。
- 增加纯进程内 HTTP 合成基准：真实认证/Handler/缓存/日志链，存储用固定内存源和查询函数。
  对比缓存开关，记录吞吐、平均/P95/P99、失败率；测量不含真实 Redis/Mongo、网络容量。
  真实存储、Redis 日志重试/丢弃及生产容量待单独授权环境压测，不编造门槛。

## 安全与风险

只使用合成凭据及数据，文件日志仅写测试临时目录；不得连接业务服务、初始化数据或部署。
不接入报警、监控平台，不实现暂缓的 SHA-256 转换服务。请求 ID 不是安全令牌或分布式 Trace。
性能数值受开发机调度影响，比较必须使用同硬件、Go、并发、数据与日志设置。
回滚本次源码/基准即可，无数据迁移；新增日志字段需消费者容忍额外字段。

## 顺序、验收与命令

1. 先加回归用例，复现未查得 ERROR 和日志无法关联；再最小修复日志，验证响应未改变、
   分类不泄漏底层错误、ID 一致且请求间不同。
2. 移动共享契约，集中有效期策略，保留直读/缓存边界测试；检查 Redis 不再 import configdata。
3. 建立可复跑隔离基准与实测报告，保留历史报告，移除无实测依据的预期性能承诺。
4. 同步索引及事实，执行 gofmt、go vet ./...、go test -race ./...、go build ./...、
   go mod verify、独立 Redis CLI 测试和 git diff --check；检查相对链接。

不自动提交；真实 Redis/Mongo 性能基线仍待建立。
