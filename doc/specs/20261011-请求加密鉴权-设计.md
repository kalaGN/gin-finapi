# Loan 请求契约与鉴权：设计

> 2026-10-11 后续变更：静态 API_KEY/SECRET_KEY 已由 Redis 独立 String 凭据替代，见 [API Key Redis 设计](20261011-APIKey%20Redis存储-设计.md)。本文其余请求/签名契约保留。


状态：已修正强制 AES 契约；文件名保留以追溯被撤销方案。

## 处理链路

main → bootstrap → Recovery/CORS/元数据 Logger/配置 IP 限流 →
LoanAuth 单次 JSON 解析和字段校验 → API_KEY 匹配 → timestamp/sign →
类型化请求存入 Gin Context → LoanHandler 生成 SID → 注入查询(phone 原值) → 原错误映射/响应。

/health 保持公开。共享 DTO 在 pkg/request；bootstrap.NewRouter 注入 Mongo 查询闭包、SID 和 Logger，并装配认证与限流；main 只调用创建入口。
Handler 不依赖解密器、不读取全局配置；Mongo 客户端生命周期沿用原实现。

## phone 与签名契约

phone 是非空 JSON 字符串；签名始终使用收到的原始完整值。
32 位十六进制值按 MD5 处理，直接截前 20 位查 t，大小写保留。
64 位十六进制值按 SHA-256 处理：TODO 接入转换服务，取得原手机号 MD5 后截前 20 位。
服务未接入时返回 503/9002，停止 SID 生成和查询；不能用 MD5(SHA256 字符串)替代映射。
20 位缩短标识及其他历史非空标识仍原样查询，不做 AES 解密或格式收紧。

签名参数仍为 phone/pcode/apikey/timestamp，按 key 排序拼接并附加 SECRET_KEY 后计算大写 MD5。
nonce 和 URL Query 不参与，保持历史实现；timestamp 为过去五分钟内的 Unix 毫秒。
本轮保留单个配置 API_KEY 校验，历史多账号方案不实施。

## 修正记录与安全

原 AES 强制解密把既有查询标识误判为无效密文。先增加用户示例的失败回归测试，
确认查询未执行且返回 400/1002，再删除解密步骤和 PHONE_AES_KEY 配置依赖。
本轮自己新增的 AES 实现和仅验证撤销契约的测试移除，以原值查询回归取代。

请求 Body 限制 64 KiB，要求单个 application/json；日志只记录安全元数据，
Handler 不输出可能包含查询值或凭据的底层错误。MD5 签名和五分钟内可重放的边界保持，
不引入 nonce 存储；传输仍应使用 HTTPS。

## 配置与客户端请求生成

必填 API_KEY、SECRET_KEY 和 Mongo 连接配置；RATE_LIMIT_REQUESTS/RATE_LIMIT_WINDOW
默认 5000/1s。PHONE_AES_KEY 不再需要，遗留值不会生效。

Go 客户端构造参数示例（读取受控环境中的测试凭据；不要将请求输出写入生产日志）：

```go
params := map[string]interface{}{
    "phone": "r707qyr0k2xmucjp7lz0", // 隔离测试集合的原查询标识
    "pcode": 10001,
    "apikey": os.Getenv("API_KEY"),
    "timestamp": time.Now().UnixMilli(),
}
params["sign"] = utils.GenerateSign(params, os.Getenv("SECRET_KEY"))
// 使用 encoding/json 序列化 params，以 application/json POST /loan。
```

客户端可传完整 MD5 或既有缩短标识，保证 API_KEY 匹配、SECRET_KEY 一致和实时 timestamp/sign。
SHA-256 转换服务的接口、认证、超时和错误契约需接入时另行确认。
部署时重启新二进制，不运行 Mongo 重建工具或修改数据库；本轮不操作运行服务。
