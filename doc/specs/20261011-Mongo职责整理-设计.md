## 目标与事实来源

整理 Mongo 内部职责，暂不改变数据格式。当前 `pkg/mongo/mongo.go` 同时负责客户端管理、
配置补全、查询、错误分类、gzip 解压和字段映射。
事实来源：该文件、`mongo_test.go`、`bootstrap/route.go`、`pkg/config/config.go`。
工具链：Go 1.24.0，toolchain go1.24.10；Mongo Driver 1.17.2，来源为 `go.mod`。

## 文件职责与依赖

保持同一个 `pkg/mongo` 包，不新增子包、接口或 Repository 层：

| 文件 | 职责 |
| --- | --- |
| `mongo.go` | Config、GetMongo 入口、配置补全、集合选择、FindOne、查询超时解析 |
| `client.go` | clientManager、GetClient、Close、池初始化及关闭；保留旧 connectToMongoDB |
| `codec.go` | gzipDecompress、decodeUserData、ProcessUserData 和六变量映射 |
| `errors.go` | 三个导出错误及 classifyMongoError |

链路仍为 GetMongo → GetClient → FindOne → decodeUserData → gzipDecompress → ProcessUserData。
查询入口保留 `return decodeUserData(foundDoc.V)`；解码函数不承担数据库 I/O。
使用中文注释和 gofmt；尽量原样移动函数，仅调整文件与必要 import。
查询和文档的匿名结构体改为包内私有类型，保留字段与 BSON 标签，便于直接测试实际契约。

## 兼容边界与非目标

- 导出函数签名和包路径不变；BSON 查询仍为 `t=Query`，文档仍为字符串 t 和二进制 v。
- v 仍为 gzip 压缩的逗号分隔整数文本，严格六字段映射到 var100001–var100006。
- 缺字段、多字段、非整数和坏 gzip 仍报 ErrInvalidData；其他错误分类和错误链不变。
- 配置补全、默认集合、池参数、连接与选服超时、查询超时回退不变。
- 懒连接、失败后重试、全局客户端、Close 后可重建的行为不变。
- 不修改 HTTP、phone、签名、日志内容或启动关闭顺序。
- 不修改 Schema、数据、索引、配置、依赖、CI 或部署；无数据迁移或数据回滚。
- 不连接真实数据库，不运行数据初始化 CLI，不提交、推送或重启服务。
- 不新增解压上限、重试、事务或性能策略；没有新的性能目标或性能提升声明。
- 旧 connectToMongoDB 未被调用但本次不删除；其重复连接逻辑另行确认处理。
- GetMongo 的 DSN 参数与全局连接配置并非完全隔离，本次保留现状，不调整其语义。
- 不输出或提交密钥、连接串和个人数据。
